# Переезд НейроЯги с Railway на Amvera

## Сначала о главном

На скриншоте Railway написано «Развертывание временно приостановлено». Это не память:
462 МБ из 8 ГБ и нулевой процессор — для сервиса с Pillow и ReportLab нормальные цифры.
Приостановка почти всегда означает исчерпанные кредиты или проблему с оплатой.

**Проверьте в Railway раздел Usage и баланс.** Если дело в оплате зарубежной картой —
переезд оправдан. Если просто кончились кредиты и карта работает, можно остаться:
миграция займёт вечер, а проблему решит пополнение.

## Что хорошо и что рискованно в Amvera

**За переезд:**
- оплата российской картой, без танцев с зарубежными платежами;
- серверы в России — быстрее для ваших кондитеров;
- постоянный диск `/data`, файлы переживают перезапуск;
- поддержка на русском.

**Против и о чём надо знать:**
- на балансе 10 ₽, нужно пополнить до запуска;
- в шапке висит предупреждение про атаку БПЛА на ЦОД Яндекса и перенос региона
  Москва_0 в Москва_1 — к надёжности площадки стоит относиться трезво и держать
  резервную копию кода на GitHub, что у вас уже есть;
- интерфейс и формат конфигурации отличаются от Railway, детали ниже сверяйте
  с документацией Amvera: она меняется, а я вижу только скриншот.

**Сервис останется на двух ногах в любом случае:** Google-таблица с кредитами и ЮKassa
работают отдельно от хостинга, их трогать не нужно.

## Шаг 1. Пополните баланс

В Amvera нажмите на сумму «10.00 ₽» в шапке и пополните счёт. Списания идут только
за запущенные контейнеры, создание проекта бесплатно.

## Шаг 2. Создайте приложение

1. «Продукты» → «Приложения» → «Создать проект».
2. Тип — приложение на Python.
3. Источник кода — подключите GitHub-репозиторий `midva20095-png/neyroyaga-cakes`
   либо загрузите файлы вручную, если подключение GitHub недоступно.

## Шаг 3. Проверьте файл конфигурации

В проекте уже лежит `amvera.yml`:

```yaml
meta:
  environment: python
  toolchain:
    name: pip
    version: 3.12
build:
  requirementsPath: requirements.txt
run:
  persistenceMount: /data
  containerPort: 80
  command: uvicorn main_cake:app --host 0.0.0.0 --port 80
```

Если Amvera при сборке предложит свой мастер настройки, сверьте поля с этими
значениями. Главное: команда запуска и порт 80.

## Шаг 4. Задайте переменные окружения

В разделе «Переменные» добавьте те же, что были на Railway:

| Переменная | Что это |
|---|---|
| `GEMINI_API_KEY` | ключ Google Gemini |
| `GOOGLE_SCRIPT_URL` | адрес `/exec` скрипта Google-таблицы |
| `YOOKASSA_SHOP_ID` | идентификатор магазина ЮKassa |
| `YOOKASSA_SECRET_KEY` | секретный ключ ЮKassa |
| `OUTPUT_DIR` | `/data/generated` — чтобы готовые файлы лежали на постоянном диске |

Значения возьмите из Railway: вкладка «Переменные» вашего сервиса.

## Шаг 5. Запустите и проверьте логи

После сборки откройте логи. Должны появиться строки:

```
INFO:     Started server process
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:80
```

Если сборка падает на установке зависимостей, проверьте версию Python: нужна 3.12 или новее.

## Шаг 6. Проверьте адрес и работу сервиса

Amvera выдаст адрес вида `имя-проекта.amvera.io`. Откройте его в браузере: должен
открыться интерфейс студии. Проверьте по очереди:

```
https://ваш-адрес/api/config
https://ваш-адрес/api/objects
https://ваш-адрес/api/backgrounds
https://ваш-адрес/api/gallery
```

Первый вернёт цены, остальные — списки. Если списки пустые, папки `objects`,
`backgrounds` или `gallery` не попали в сборку.

## Шаг 7. Переключите блок Tilda на новый адрес

В файле `build_tilda.py` найдите строку с адресом и впишите новый:

```python
ORIGIN = "https://ваш-адрес.amvera.io"
```

Затем пересоберите блок:

```
cd ~/Desktop/neyroyaga-cakes && python3 build_tilda.py
```

Скопируйте получившийся `tilda_block.html` целиком и вставьте в блок Tilda вместо
старого кода. Опубликуйте страницу.

Если правите блок вручную, замените в нём одну строку:

```js
const ORIGIN='https://neyroyaga-cakes-production.up.railway.app'
```

на адрес Amvera.

## Шаг 8. Перенастройте ЮKassa

В личном кабинете ЮKassa замените адрес уведомлений (webhook) на новый:

```
https://ваш-адрес.amvera.io/api/yookassa-webhook
```

Без этого оплата пройдёт, а кредиты не начислятся.

## Шаг 9. Проверьте полный цикл

1. Войдите на сайт, убедитесь, что баланс подтянулся из таблицы.
2. Соберите макет в песочнице и скачайте PDF.
3. Скачайте JPG.
4. Купите макет из галереи.
5. Пополните баланс на минимальную сумму и проверьте, что кредиты начислились.

## Шаг 10. Выключите Railway

Только после того, как всё заработает: остановите сервис на Railway, чтобы он не
тратил деньги. Репозиторий на GitHub оставьте — он общий для обеих площадок.

---

## Если что-то пойдёт не так

| Симптом | Причина |
|---|---|
| Белая страница по адресу Amvera | приложение слушает не тот порт, проверьте `containerPort: 80` и команду запуска |
| Библиотека объектов пуста | папка `objects` не попала в сборку или нет `titles.json` |
| «Сервер недоступен» в блоке Tilda | в блоке остался старый адрес Railway |
| PDF скачивается, но через час ссылка мертва | `OUTPUT_DIR` не указывает на `/data` |
| Оплата проходит, кредиты не начисляются | не поменян webhook в ЮKassa |
| Вход не работает | не задан `GOOGLE_SCRIPT_URL` |

## Про память

Пиковое потребление при сборке PDF я измерил: около 210 МБ на лист с двенадцатью
круглыми макетами. Это нормально для Pillow: лист A4 в 300 DPI — это 2480×3508
пикселей, примерно 26 МБ в памяти на каждую копию при обработке.

При выборе тарифа на Amvera берите не меньше 1 ГБ памяти, с запасом на одновременные
заказы. Процессор почти не нагружается, упор именно в память.
